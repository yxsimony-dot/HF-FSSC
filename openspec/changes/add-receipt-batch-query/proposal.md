## Why

现有“发送回单”按钮只能进入“电子回单”页面，用户仍需根据本地 PDF 文件名逐个复制业务流水号并手动查询。需要把目录中的回单文件转化为可控的顺序查询任务，减少重复操作，并明确展示未查询到的业务流水号。

## What Changes

- 在顶部任务栏中增加回单目录选择入口，并持续显示当前选定的目录路径。
- 从所选目录第一层读取 `.pdf` 文件，按文件名升序排列，并以不含扩展名的文件名作为业务流水号。
- 扩展“发送回单”流程：进入“电子回单”页面后，逐个填写业务流水号并触发“查询”。
- 每次查询完成后，只有结果表格中存在业务流水号完全相同的记录才判定成功。
- 汇总查询不到、超时或页面异常的流水号；全部成功时显示统一成功提示。
- 继续坚持 DOM 优先、UI Automation 回退，并禁止使用固定坐标或鼠标移动。
- 本次不上传 PDF、不选择表格记录，也不执行真正的回单发送操作。

## Capabilities

### New Capabilities

- `receipt-batch-query`: 定义回单目录选择与展示、PDF 业务流水号提取、电子回单顺序查询、结果判定和最终汇总反馈。

### Modified Capabilities

无。

## Impact

- 修改 `FSSCWebLauncher/MainWindow.xaml` 和 `FSSCWebLauncher/MainWindow.xaml.cs`，并可能增加少量同项目内的结果模型或结果展示窗口。
- 继续使用现有 WPF、WebView2、Windows UI Automation 和 .NET 8 能力，不增加第三方运行依赖。
- 需要持久化最后一次选定的回单目录，并在启动时验证该目录是否仍然存在。
- 网站查询过程为异步行为，实现必须等待每一次查询完成后才能处理下一个流水号。
