## Context

当前工作区为空，参考工程 `F:\USB-Web-Launcher\PROJECT` 使用 .NET 8 WPF 和 `Microsoft.Web.WebView2` 承载网页，并以 Windows x64 自包含目录发布。参考工程同时包含大量与本需求无关的 USB、认证、导出、更新和安装逻辑，因此本变更采用独立最小工程，而不是复制或裁剪原工程。

目标网址已在规划阶段通过 HTTPS 请求验证可访问。构建机已有 .NET SDK 10.0.100，且本机 NuGet 缓存中存在参考工程使用的 WebView2 版本。

## Goals / Non-Goals

**Goals:**

- 建立一个结构清楚、可独立构建的最小 WPF 应用。
- 启动时可靠初始化 WebView2，并立即加载固定的华发 FSSC 地址。
- 让网页占满窗口客户区，同时保留网站自身的导航、登录和下载行为。
- 生成与参考工程交付方式一致的 Windows x64 自包含发布目录。
- 对浏览器初始化和首次导航失败提供最小错误反馈。

**Non-Goals:**

- 不复用参考工程的 Core、Windows、Broker 或网页脚本项目。
- 不实现浏览器工具栏、用户配置、网址切换、自动登录或网页内容注入。
- 不构建安装器，不创建桌面快捷方式，不实现自动更新。
- 不捆绑 WebView2 Evergreen Runtime，也不对目标网站的业务流程作兼容性承诺。

## Decisions

### 1. 使用独立的单项目 WPF 结构

创建一个 `FSSCWebLauncher` WPF 项目，目标框架为 `net8.0-windows10.0.19041.0`，平台固定为 x64。应用只包含启动入口、主窗口和必要的 WebView2 初始化代码。

选择该方案是因为它与参考工程的网页承载方式一致，同时能彻底隔离参考工程的业务依赖。备选方案是复制参考项目后删除功能，但这会保留无关项目引用、配置和潜在副作用。

### 2. 固定使用 WebView2 作为网页承载层

项目引用与参考工程一致的 `Microsoft.Web.WebView2` 版本 `1.0.4191.47`。主窗口仅放置一个拉伸填满客户区的 WebView2 控件，不增加自定义页头、地址栏或工具按钮。

备选方案是调用系统默认浏览器，但这不符合“与参考工程相同桌面外壳”的目标；使用 CEF 或 Electron 则会引入更大的运行包和不同技术栈。

### 3. 显式初始化浏览器环境和用户数据目录

窗口加载时调用 WebView2 环境创建与控件初始化 API。用户数据目录固定放在当前用户的 `%LOCALAPPDATA%\FSSCWebLauncher\WebView2`，避免在只读安装目录或发布目录旁写入浏览器缓存。

初始化成功后，通过一个只读常量导航到目标地址。初始地址不可通过 UI 修改，但后续由网站自身发起的正常导航和重定向不受限制。

### 4. 只实现必要错误反馈

捕获环境创建、控件初始化和初始导航失败。错误通过简短中文消息显示，不增加重试页、诊断导出或环境安装入口。错误文本避免暴露不必要的内部堆栈信息。

### 5. 采用自包含、多文件发布

发布参数使用 `win-x64`、`SelfContained=true`、`PublishSingleFile=false` 和 `PublishTrimmed=false`。产物入口命名为 `FSSCWebLauncher.exe`，发布目录整体作为交付物。

这与参考工程的实际发布规则一致，并降低 WPF/WebView2 在单文件提取和裁剪方面的兼容风险。代价是发布目录包含较多运行时文件且体积较大。

### 6. 验证聚焦于边界而非网站业务

自动验证覆盖还原依赖、Release 构建和自包含发布成功，并检查发布目录存在主 EXE 与 WebView2 本机加载器。人工冒烟验证应用启动、窗口内容无额外工具栏、固定网址加载以及关闭后进程退出。

目标网站的登录、权限、网络策略和服务器内容不由本应用控制，因此不作为实现正确性的自动测试前提。

## Risks / Trade-offs

- [运行机器缺少 WebView2 Runtime] → 启动时捕获初始化异常并显示明确提示，交付说明列出运行条件。
- [目标网站不可用或受企业网络限制] → 将导航错误与应用初始化错误分开提示，不伪装为应用成功。
- [网站未来依赖特殊浏览器策略或外部组件] → 保持标准 WebView2 行为，不注入脚本；新增适配必须作为后续独立变更处理。
- [自包含目录体积较大] → 接受该代价以换取无需安装 .NET Runtime，并明确整个目录必须一起保留。
- [未签名 EXE 可能触发 Windows 安全提示] → 本变更不虚构发布者身份；如需代码签名，后续单独规划证书与签名流程。

## Migration Plan

1. 在当前工作区创建全新的 WPF 项目，不修改参考工程。
2. 完成构建和冒烟验证后，发布到新的空目录。
3. 将完整发布目录交付给用户，由 `FSSCWebLauncher.exe` 启动。
4. 回滚时关闭应用并移除该独立目录；应用不注册系统服务、计划任务或卸载项。
