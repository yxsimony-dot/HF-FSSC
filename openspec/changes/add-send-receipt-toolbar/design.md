## Context

现有应用是单窗口 .NET 8 WPF 程序，窗口客户区仅包含一个 WebView2，并使用固定用户数据目录保持网站登录状态。现场只读检查确认：登录后的“电子回单”在 WebView2 可访问性树中表现为 `MenuItem`，名称为 `file-done 电子回单`，支持 `InvokePattern`；页面中还存在名称为“电子回单”的标签页，因此不能只按文本选择任意元素。

## Goals / Non-Goals

**Goals:**

- 让顶部区域能够继续追加后续任务按钮，而不改变 WebView2 初始化与登录状态管理。
- 以网页 DOM 操作为主路径，并以控件语义为依据精确选择站内菜单项。
- 在 DOM 不可用时提供不依赖坐标的系统可访问性回退。
- 保持错误处理简洁，不让失败操作误触相似入口。

**Non-Goals:**

- 不自动登录，不读取或保存网站账号密码。
- 不执行进入“电子回单”之后的查询、选择、上传或真正发送流程。
- 不使用固定坐标、鼠标移动或图像识别。
- 不修改目标网站、参考工程或现有 WebView2 用户数据目录。

## Decisions

### 1. 使用 WPF 原生任务栏占据固定顶部行

主窗口根网格改为上下两行：顶部为固定高度的任务栏，底部由 WebView2 填满。首个按钮直接绑定窗口点击事件。该结构足以支持后续继续追加按钮，又不会为当前单按钮需求引入命令框架或额外视图模型。

### 2. DOM 查找采用菜单语义和精确文本

按钮点击后通过 `CoreWebView2.ExecuteScriptAsync` 执行小型脚本，仅在 `li.ant-menu-item` 或 `[role="menuitem"]` 中查找规范化文本精确等于“电子回单”的可见元素。若未找到，则精确查找并点击“档案收集”菜单标题，短暂等待页面展开后再次查找。

不选择全页面任意同名文本，因为当前页面同时存在“电子回单”标签页；不使用 URL 硬编码，因为现场可见的路由标识属于网站内部实现，菜单点击更符合网站自身导航状态管理。

### 3. 使用 UI Automation InvokePattern 作为第二路径

当两次 DOM 查找均失败时，在后台线程中从当前窗口的可访问性树查找 `ControlType.MenuItem`。名称仅接受“电子回单”或以空格加“电子回单”结尾的值，以兼容当前图标名称前缀，同时排除“电子回单业务查询”。找到支持 `InvokePattern` 的已启用、非离屏项目后直接调用。

该回退比鼠标坐标稳定，并已经在用户当前登录实例上只读验证。固定坐标方案不纳入实现。

### 4. 将按钮状态与浏览器初始化状态分离处理

按钮始终可见；点击时检查 `CoreWebView2`，尚未就绪则提示稍后重试。执行识别期间临时禁用按钮以避免重复触发，结束后恢复。未找到目标时使用 WPF 消息框提示用户确认已登录并进入正确页面。

### 5. 发布到新的独立目录

当前旧版发布程序正在运行，并占用原发布目录中的文件。新版本发布到 `publish/FSSCWebLauncher-send-receipt-win-x64`，避免覆盖运行中的 EXE 和依赖。用户确认新版本后，可自行关闭旧版并改用新目录。

## Risks / Trade-offs

- [网站更新菜单标签、角色或样式类] -> DOM 路径失败后使用可访问性菜单项回退；两条路径都失败时明确提示，不误点其他入口。
- [菜单位于不可直接访问的跨域框架] -> 顶层 DOM 路径可能看不到元素，但 WebView2 可访问性树仍可调用现场已验证的菜单项。
- [可访问性名称中的图标前缀变化] -> 以菜单控件类型和目标名称后缀共同判断，不依赖当前固定的 `file-done` 字符串。
- [同名标签页被误选] -> 两条路径均限定控件语义为菜单项。
- [用户尚未登录] -> 不推断登录状态，只在找不到入口时提示用户登录并重试。

## Migration Plan

1. 完成 Release 构建与静态验证。
2. 发布到新的独立目录，不影响当前运行实例。
3. 关闭旧版后，从新目录启动并使用原有 WebView2 用户数据目录恢复登录状态。
4. 如需回滚，关闭新版并重新运行原发布目录中的 EXE。
