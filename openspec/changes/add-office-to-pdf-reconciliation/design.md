## Context

见 `proposal.md`。当前对账队列递归纳入 PDF 和图片，工作项保存 `FileName`、`ArchiveName`、`SourcePath` 和 `RelativePath`。`ReconciliationPageClient` 在唯一精确匹配且附件数量为 `0` 后直接上传 `SourcePath`，`ReconciliationBatchRunner` 在网页确认上传成功后移动同一个源文件。

Office 文件需要把“原始业务文件”和“实际上传文件”分开：查询仍使用原始文件名，网页上传的是转换产生的临时 PDF，最终归档的是原始 Office 文件。WPS Writer 的 `KWPS.Application` 已验证可将 `docx` 导出 PDF；WPS Spreadsheets 的 `KET.Application` 已生成有效 `xlsx` PDF，但自动化调用可能在输出完成后仍不返回，因此转换不能在 WPF 主进程内直接等待。

## Goals / Non-Goals

**Goals:**

- 在不改变 PDF 和图片现有路径的前提下，为四种 Office 扩展名增加按需转换。
- 让网页查询和附件判断先于转换，避免为已有附件或查询失败项目启动 WPS。
- 隔离 WPS 自动化卡死，并在超时后基于进程清理和 PDF 完整性决定能否继续。
- 明确区分原始源文件、临时上传文件和最终移动目标，避免误删或误移动。
- 让转换失败只影响当前项，并在结果弹窗中提供可核对阶段和原因。

**Non-Goals:**

- 不安装、修复或升级 WPS Office。
- 不支持 Microsoft Office COM、LibreOffice 或在线转换服务作为备用后端。
- 不修改 Word 排版、Excel 页面设置或打印区域，沿用 WPS 默认 PDF 导出语义。
- 不支持受密码保护文件的自动解密。
- 不把临时 PDF 保存到“对账已完成目录”，也不把它作为用户档案长期保留。

## Decisions

### 1. 工作项区分原始文件类型，归档身份始终指向原文件

扩展 `ReconciliationWorkItem`，增加可判定的文件种类：

```text
DirectUpload: PDF 或支持的图片
OfficeWord:   doc / docx
OfficeExcel:  xls / xlsx
```

`SourcePath`、`FileName` 和 `RelativePath` 始终代表原始文件。`ArchiveName` 继续只移除最后一个扩展名。临时 PDF 不写回工作项的源字段，而由一次性上传载荷表达。

相比在转换后把 `SourcePath` 替换为 PDF 路径，这个模型能保证上传成功后移动的是原始 Office 文件，汇总中显示的也是用户能在对账目录找到的原文件。

### 2. 将单项流程拆成网页检查、上传载荷准备和网页上传

现有页面逻辑需要保留“上传前重新确认唯一行及附件数量”的保护，因此单项处理采用以下顺序：

```text
[查询档案并读取附件数量]
              |
      +-------+-------+
      |               |
  已有附件/失败      附件为 0
      |               |
   返回终态      [创建上传载荷]
                      |
            +---------+---------+
            |                   |
       PDF/图片原路径       Office 临时 PDF
            |                   |
            +---------+---------+
                      |
          [重新验证当前档案行并上传]
                      |
             [释放上传载荷]
                      |
       [成功时移动原始 SourcePath]
```

页面客户端负责查询、同一行证明、上传前重检和上传结果观测；上传载荷工厂负责直接文件或 Office 临时 PDF。批次执行器继续逐项等待完整终态，从而保持现有严格串行语义。

备选方案是在建立队列时预先转换全部 Office 文件，但会浪费时间并为已有附件项目生成无用临时文件，因此不采用。

### 3. 复用当前 EXE 的隐藏工作模式作为转换子进程

不新增需要单独部署的转换程序。`FSSCWebLauncher.exe` 增加内部命令行工作模式：

```text
FSSCWebLauncher.exe --office-pdf-worker <request-json-path>
```

主进程把源路径、目标 PDF 路径和文件种类写入权限受限的批次临时目录，请求文件使用随机名称。命令行只传请求文件路径，避免 Office 文件路径的引号、长度和特殊字符问题。工作模式不创建 `MainWindow`，在 STA 线程完成一次转换，写入结果 JSON 后退出。

复用同一个 EXE 可以自然进入现有自包含发布目录，不需要额外维护第二套 .NET 运行时或遗漏辅助程序。`App` 启动逻辑需要在创建主窗口前识别工作参数；普通启动路径保持不变。

### 4. 按文档类型选择 WPS 自动化入口

- `doc`、`docx` 使用 `KWPS.Application`，以不可见、只读且禁止提示的方式打开文档并导出完整 PDF。
- `xls`、`xlsx` 使用 `KET.Application`，以不可见且禁止提示的方式打开工作簿，并在工作簿级别导出 PDF。

通过运行时 COM 激活和动态调用连接 WPS，不引入 WPS 类型库引用，避免发布版绑定某个安装版本。工作进程在 `finally` 中按“文档或工作簿 -> 集合 -> Application”的顺序关闭和释放 COM 对象，禁止保存对源文件的修改。

若 ProgID 不可用、打开时出现密码或格式错误、导出调用明确失败，工作进程返回结构化失败结果。不同 WPS 版本的错误文本只用于诊断，主界面使用稳定的中文阶段说明。

### 5. 用独立进程、超时和转换拥有的进程边界隔离卡死

主进程隐藏启动工作进程并设置转换超时。工作进程及其新建子进程纳入带“关闭时终止”语义的 Windows Job Object；超时后主进程终止该作业并等待进程退出。清理逻辑不得按进程名全局结束 WPS，也不得终止转换开始前已经存在的 WPS 进程。

若 WPS COM 使用方式无法证明进程属于本次转换，应用宁可将当前项判定为转换失败，也不强制关闭用户已经打开的 WPS。正常路径仍优先调用文档关闭和 `Application.Quit`。

这个边界解决已观察到的 Excel 情况：PDF 可能已经完整生成，但 COM 调用迟迟不返回。达到超时后先终止本次转换拥有的进程，再验证输出：

- 工作进程正常报告成功时，输出仍必须通过 PDF 完整性校验；
- 工作进程明确报告失败时，即使存在残留 PDF 也判定失败；
- 工作进程超时但清理后 PDF 完整且大小稳定时，可继续上传；
- 超时且输出不存在、仍变化或不完整时，返回“转换超时”。

### 6. PDF 校验采用无额外依赖的结构和稳定性检查

临时 PDF 只有同时满足以下条件才可上传：

- 路径位于当前批次临时目录内；
- 文件存在且可独占或共享读取；
- 文件长度大于合理的最小值；
- 在短间隔的连续检查中长度和最后写入时间保持稳定；
- 文件头包含 `%PDF-`；
- 文件尾部有效范围内包含 `%%EOF`。

这不是完整 PDF 语义解析，但足以拦截空文件、半写入文件、错误格式和绝大多数被强行终止后的残缺输出，同时不为单一功能增加大型 PDF 依赖。若后续发现 WPS 输出存在结构校验仍无法覆盖的损坏样本，再引入专用解析库。

### 7. 临时目录和上传载荷使用一次性生命周期

每次发送对账建立独立临时根目录，例如：

```text
%TEMP%\FSSCWebLauncher\reconciliation\<batch-id>\<item-id>.pdf
```

Office 上传载荷同时保存 `UploadPath`、`IsTemporary` 和清理结果。直接上传载荷指向原始 PDF 或图片且不参与临时删除。

临时 PDF 在上传成功、上传失败、上传前重检失败或异常退出路径中都通过 `finally` 清理。单项首次删除失败时记录警告，批次结束再次清理整个批次临时目录；程序启动或批次开始时可顺带清理超过保留期限的旧临时目录。清理失败不反转已经由网页证明的上传成功，也不把临时 PDF移动到完成目录。

### 8. 上传成功后仍复用原文件移动规则

网页确认上传成功后，批次执行器将原始 `ReconciliationWorkItem.SourcePath` 交给现有保留 `RelativePath` 的移动逻辑：

- 完成目录有效：移动原始 `doc`、`docx`、`xls` 或 `xlsx`；
- 未配置有效完成目录：保留原始文件并返回“上传成功未移动”；
- 目标冲突或移动失败：不覆盖，保留原始文件并返回移动失败。

临时 PDF 的删除与原文件移动是两个明确动作。若临时清理失败，结果保留上传和移动的真实终态，并附加清理警告；若上传失败，则不进入原文件移动阶段。

### 9. 增加转换终态和警告信息

`ReconciliationItemStatus` 增加 `ConversionFailed`。结果模型增加可选警告集合，用于表达“上传和移动已成功，但临时文件首次清理失败”等不应覆盖主终态的问题。

汇总窗口新增“转换失败”数量和明细，并在需要复核的项目中显示：

- 原始相对路径；
- 档案名称；
- 原始文件类型；
- 失败阶段和稳定的中文原因；
- 临时文件清理警告。

相比把转换失败归入“上传失败”，独立分类能直接判断问题发生在本机 WPS 还是网页上传。

### 10. 验证分为无 WPS 固件和真实 WPS 冒烟两层

自动验证使用可替换的转换进程启动边界，覆盖：

- 四种 Office 扩展名和大小写；
- 仅在附件为 `0` 后调用转换；
- 直接文件不调用转换；
- 正常成功、明确失败、超时有效 PDF、超时无效 PDF；
- 上传路径为临时 PDF，移动路径为原始 Office 文件；
- 所有终态的临时清理、移动和汇总；
- 单项失败后继续下一项。

真实环境冒烟验证分别使用可公开测试的 `doc`、`docx`、`xls` 和 `xlsx` 样本，确认 WPS 实际输出和进程清理。由于目前只实测过 `docx` 和 `xlsx`，发布前必须补齐旧格式 `doc` 和 `xls`。

## Risks / Trade-offs

- [WPS 版本之间的 COM 方法或参数存在差异] -> 使用已注册 ProgID、运行时调用和分类型错误，真实验证覆盖四种格式；不绑定单一版本类型库。
- [Excel 已写完 PDF 但 COM 不返回] -> 超时后清理转换拥有的进程，再以稳定性和 PDF 标记校验决定是否接受输出。
- [强制清理误伤用户正在使用的 WPS] -> 不使用全局 `taskkill` 或按名称清理，只终止 Job Object 内和能够证明由本次转换创建的进程；无法证明时保护性失败。
- [源文件带密码、损坏或包含 WPS 不支持内容] -> 当前项转换失败并保留原文件，汇总中显示原因，不自动修改源文件。
- [复杂 Excel 工作簿的分页与用户预期不同] -> 沿用 WPS 工作簿级默认 PDF 导出，不在本次变更中调整打印区域和页面设置。
- [临时 PDF 删除失败] -> 记录警告、批次结束重试并清理陈旧目录；不移动临时 PDF，也不篡改已确认的网页上传结果。
- [同一档案在转换期间被其他人上传附件] -> 上传前重新验证唯一档案行及附件数量，发生变化时删除临时 PDF并保留原文件。

## Migration Plan

1. 扩展对账队列和工作项类型识别，保持原字段含义与排序不变。
2. 增加上传载荷抽象，并把网页查询、载荷准备和上传重检串成单项状态机。
3. 增加同 EXE 隐藏转换工作模式、WPS Writer/Spreadsheets 转换和结构化结果。
4. 增加父进程超时、Job Object 清理、PDF 稳定性校验和批次临时目录清理。
5. 扩展批次结果状态、警告信息和结果弹窗。
6. 运行现有回单与对账验证，再补充模拟转换及四种真实 WPS 样本验证。
7. 执行 `win-x64` Release 自包含发布，同步全部最新文件到 `publish/FSSCWebLauncher`。
8. 从 `publish/FSSCWebLauncher/FSSCWebLauncher.exe` 启动普通界面，验证按钮和现有流程；再从发布目录验证 Office 转换工作模式及实际上传链路。

回滚时关闭发布版和本次转换工作进程，恢复上一份发布目录。设置文件和用户目录结构不新增迁移字段；遗留批次临时目录可安全删除。
